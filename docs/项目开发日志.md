## 二、本轮迭代时间线（提示词 → 实现）

### 1. 面板布局与初始参数
- **提示词**：01 视点导航面板遮挡文字应下移；「北看台三层顶」机位略高调低；
  屋盖透明度初始值调为 100；提前设计「曼联球员」导航栏与球员卡占位。
- **实现**：`.view-panel` top 400→462px；`seat-upper-n` 相机 y 42→38（34 会穿进看台）；
  `state.roofOpacity` 1→100；新增 `PLAYERS` 数据契约 + 球员抽屉（P 键）。

### 2. 阵容站位视角（几何体人形）
- **提示词**：设计类似足球游戏阵容图的视角——场上每个位置用简单几何体，鼠标靠近
  显示对应球员卡；起始位置在死忠区，门将靠近死忠区。几何体用胶囊体+球体、主色红；
  总览机位锁定；靠近时推近锁定；卡面翻转式。
- **实现**：
  - `data.js`：`LINEUP`（4-2-3-1 草坪坐标，[推定]）+ `VIEWPOINTS` 16 号机位；
  - `stadium.js`：胶囊体(0.42×1.25)+球头(0.32) 红色人形 + 半径 1.9m 隐形命中球；
  - `app.js`：屏幕投影 52px 靠近判定 → 推近锁定（`flyTo` pose 覆盖）→ 翻转卡浮层；
  - **门将对齐**：`findPitchFrame()` 在切分模型里找两端球门白框（见第 8 条）。

### 3. 面板重构
- **提示词**：鸟瞰部分 = 视点导航，人眼高度 = 观众视角，阵容视角单独一个折叠面板；
  左右各两个折叠面板，同侧同时只能开一个。
- **实现**：`panel-col` flex 容器左右两列（01 视点导航+02 观众视角 | 03 阵容站位+
  04 控制台+05 队史），互斥展开；移动端 `display: contents` 解散回退底部抽屉。

### 4. 主教练与交互细节
- **提示词**：教练区加同款几何体主教练（空白卡占位）；悬停效果照常；退出锁定后
  等 1s 再进行下次判定；卡面以胶囊底部为坐标、完全盖住几何体，大小 1.2 倍。
- **实现**：`COACH` 数据 + 空白占位卡（`is-blank` 样式）；`lineupRearmAt` 1s 冷却；
  卡面锚点改为脚底、宽 300px、相机拉远到 ~12m 保证覆盖。

### 5. 替换功能（换人）
- **提示词**：曼联球员部分中的球员卡可与场上任意球员对调，即替补功能。
- **实现**：运行时槽位 `lineupSlots`（站位不变、人员可换）+ 替补池 `benchPool`，
  **不写回 data.js**（数据契约保持静态）。抽屉分「场上十一人 / 替补席」，
  替补卡「换上」→ 换人模式 → 点场上人形（pointerup）或阵容名单行 →
  `substitutePlayer()` 对调并同步人形卡面/名单/抽屉；Esc 取消。

### 6. 阵型切换
- **提示词**：搜集热门阵型并加阵型变更功能；换人和阵型替换时视角换成高空俯视图。
- **实现**：
  - 数据：`data.js` `FORMATIONS` 8 套（4-2-3-1/4-3-3/3-4-2-1/4-1-4-1/4-4-2/3-5-2/
    5-3-2/3-2-4-1），slots 顺序必须与 `LINEUP.members` 槽位序一致，来源注记引用
    英超官方 2024/25 统计（4-2-3-1 408 次主流、3-4-2-1 最大上升者等）；
  - 交互：阵容面板 FORMATION 网格选择 → 人形补间走位（`formationTween`，animate
    逐帧 lerp）→ 相机先升草坪正上方 118m 俯视、走位完回落总览；换人流程同俯视。

### 7. 显隐 / 平躺 / 互斥
- **提示词**：几何体不用到阵容时才显现，阵容抽屉下加显隐功能；俯视图时几何体平躺
  方便看清变化；显示球员卡面和阵型切换只能同时运行一个，否则抢视角。
- **实现**：面板「人形显示」开关（`lineupFiguresManual`，任意机位常显）；
  `figureLieTarget/figureLieAngle`（±π/2 绕 Z 轴平躺、头朝进攻方向，animate 指数
  平滑）；互斥——阵型切换/换人前先 `unfocusLineup(true)` 收卡面，走位补间期间
  靠近判定与名单点击直接屏蔽。

### 8. 实测球场框架（关键修正）
- **提示词**：阵型在俯视图和其他视角看是倾斜的；建议先依照球场白线确认具体球场
  数据再调整，不要纯视觉判断。
- **实现**：`findWestGoalAnchor` 升级为 `findPitchFrame()`——在切分模型里按几何特征
  （宽 7.32m 级、高 2.44m 级、进深薄）找**两端**球门白框（各 4 块网格）：
  - 实测结果：**长轴偏角 -6.57°**、球场中心偏 (4.6, -2.7)m、门线间距 102.7m。
    标定用的草坪贴图主成分方向与真实白线**不重合**——这就是倾斜的根源；
  - 阵容组 `rotation.y = -6.57°` + 平移到实测中心；局部理想草坪坐标经
    `localToWorld`（cos/sin 旋转映射）落到真实白线上，教练与卡面锚点同映射；
  - 俯视相机对准实测中心、机位上方向沿长轴——白线在画面里横平竖直；
  - **坑**：west 球门线取 `union.max.x`、east 取 `union.min.x`（网向场外延，
    取朝场地一侧），否则门线间距虚大到 111m。

## 三、踩坑记录

1. **8231 端口多服务打架**：Windows 允许多个进程重复绑定同端口（SO_REUSEADDR），
   请求随机命中旧服务 → 新路径模块 404（报「Failed to fetch dynamically imported
   module」），且浏览器会**负缓存**失败模块——换新标签页才恢复。
   **重启服务前先 `taskkill //F //IM python.exe` 清干净。**
2. **并发拉大模型断流**：两条对话同时拉 29MB GLB 偶发断流——`stadium.js
   loadModel()` 已加最多 2 次自动重试。
3. **IAB 后台标签页 rAF 暂停**：自动化测试时标签页在后台则 animate 不跑
   （visibilityState 仍报 visible），依赖 animate 的事件路径全部失效而同步探针
   正常——测试前确认 rAF 存活、只保留一个标签页。
4. **草坪贴图主成分方向 ≠ 白线方向**：模型标定（`MODEL_YAW_DEG`）基于草坪网格
   PCA，与真实白线差 6.57°——涉及球场对齐的逻辑一律以 `findPitchFrame()` 的实测
   框架为准，不要改 `LINEUP`/`FORMATIONS` 的标称坐标。
5. **OrbitControls minDistance**：推近机位 9m 会被全局 `minDistance=14` 推回——
   进阵容机位时放宽到 3，离开恢复。
6. **bindPicking 曾未被调用**：看台悬停/点击拾取整条链路失效的隐性 bug，启动绑定
   序列里必须保留 `bindPicking()`。

## 四、架构约定（复现必读）

- **数据契约**：`js/data.js` 是唯一事实来源（META/PITCH/STANDS/VIEWPOINTS/
  COLORS/PLAYERS/PLAYER_CARDS/LINEUP/COACH/FORMATIONS/SOURCES/HERITAGE），
  可信度分级标注（[官方]/[文献]/[推算]/[推定]）；运行时状态（槽位/替补池/
  换人）只存在于 app.js，不写回。
- **坐标约定**：+X 东 / -X 西 / +Z 南 / -Z 北 / +Y 上，原点 = 草坪贴图中心；
  阵容局部坐标为理想草坪坐标（门将 (-50,0)），由 `lineupFrame`（实测中心+长轴角）
  映射到真实白线。
- **分层**：data.js（契约）→ stadium.js（GLB 装配/阵容几何）→ app.js（渲染/交互）。
- **Three.js 本地化**：`vendor/three.module.js` + `vendor/addons/`，importmap 映射
  `three` 与 `three/addons/`，禁止 CDN。

## 七、自定义球员卡（2026-10-25）

「曼联球员」抽屉新增自定义球员功能：表单填写姓名/号码/位置/国籍 + 背面三项数据、
成就（`年份|说明` 逐行）、荣誉，可上传卡面照片（Canvas 压缩到最长边 512 px 的
JPEG dataURL），持久化在 `localStorage`（键 `oldtrafford.customPlayers.v1`）。

实现要点：

1. **一条记录两个身份**：自定义球员把「场上身份字段 + 卡面字段」合并成同一对象，
   `customPlayers`（持久层）与 `benchPool`（替补池）持有同一引用——这样
   `cardDataFor()` 按 slug 在 `PLAYER_CARDS.players` 之后追加查自定义表，删除时
   `benchPool.indexOf()` 才能命中。
2. **自动进入所有卡面板块**：不动渲染逻辑，只把自定义球员并入替补池尾部，其余
   全部复用现有换人体系——「换上」→ `substitutePlayer()` 已会同步刷新抽屉、
   阵容名单与场上人形 `part.player`；3D 特写卡走 `fillLineupCard → cardDataFor`。
3. **无照片兜底**：`playerPhoto()` 对没传照片的自定义卡返回一张内联 SVG 深红
   渐变 dataURI，正面版式（角标/队徽/姓名/球衣）不变。
4. **删除在场上的自定义球员**：按 slug 找到占用槽位后，用 `slotName`（即原首发
   球员的 name）从 `PLAYERS.groups[0]` 找回原球员换回，再同步人形 userData。
5. **Esc 分级**：keydown 处理器最前插入 `state.customFormOpen → 收起表单`，
   避免填表时按 Esc 直接把整个抽屉关掉。

浏览器实测（`?shell=1` 测 UI 层 + `?debug=1` 测全链路）：添加 → 替补席出现
CUSTOM 卡 → 刷新持久化 → 「换上」+ 点名单完成对调 → 阵容名单与 3D 特写卡
（号码/角标/背面数据/占位底图）全部正确 → 删除场上自定义球员自动换回原首发、
localStorage 清空。
