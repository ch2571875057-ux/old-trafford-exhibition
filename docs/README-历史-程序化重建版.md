## 一、这是什么

一个**单页、纯静态、离线可跑**的球场三维展览，用于建筑展览与教学演示。它的目标不是
"做一个好看的球场"，而是**把"每一处尺寸从哪来、可信到什么程度"这件事本身做成展品**。

页面顶部始终显示模型坐标与构建统计，右侧「档案」抽屉里给出全部数据来源、精度分级与
免责声明，`js/data.js` 里每一个数值都带 `[官方]` / `[文献]` / `[推算]` / `[推定]` 证据标签。

**核心数字（由页面实时统计，非写死）**

| 项目 | 数值 | 性质 |
|---|---|---|
| 生成座席 | **76,087** | 由几何排布算出 |
| 三角面 | **1,914,946** | 运行时统计（其中座席 1,826,088） |
| 网格数 | 201 | 合并后 |
| 看台 / 层段 | 4 / 8 | 四座看台 + 四角象限 |
| 座席总排数 | 258 | 重建值 |
| 几何构建耗时 | **约 270–370 ms** | 单线程同步生成（含外观结构） |
| 场地坐标 | 53.4631°N / 2.2913°W | 公开坐标 |
| 启用年份 | 1910 | — |

> 复算方式：`node tools/check-geometry.mjs`（数据自检）与
> `node _x_check/stat_probe.mjs`（不启浏览器直接跑几何、打印 `stats`）。

**它不是什么**（详见 [第八节](#八已知偏差与诚实清单)）：

- 不是施工图，不是测绘成果，不得用于任何工程、报建或安全用途；
- 没有使用任何官方建筑图纸、点云或倾斜摄影数据（公开渠道确实取不到，见研究文档）；
- 没有复制任何受著作权保护的**照片**，也没有复制任何注册商标图形。

## 二、快速开始

ES module 在 `file://` 协议下无法加载，**必须通过本地 HTTP 服务打开**。

### 方式 1：双击启动器（推荐）

```
双击  启动.bat
```

脚本会自动探测 `python` / `py -3` / `python3`，都没有则回退到 `npx serve`，
然后在本机 8080 端口起服务并自动打开浏览器。

### 方式 2：手动起服务

```bash
# 在项目根目录（与 index.html 同级）
python -m http.server 8080
# 或
npx --yes serve -l 8080
```

然后访问 <http://127.0.0.1:8080/>。

> ⚠️ 直接双击 `index.html` 只会看到页面外壳与"无法建立三维视图"的提示面板 ——
> 这是 ES module 的协议限制，不是文件损坏。所有 JS、Three.js 都在本地 `vendor/` 下，
> 运行期**不需要联网**。

## 五、模型是怎么重建出来的

整个模型**没有导入任何外部几何文件**。`js/stadium.js` 读取 `js/data.js` 里的尺寸，
用 Three.js 的 `BufferGeometry` 逐块构造，再用 `mergeGeometries` 合并成 201 个网格。
外观上的花纹（幕墙分格、横幅字样、檐口饰带）也是运行时用 Canvas 现画成纹理的，
**项目里没有任何图片素材**：`assets/` 下只有图纸 SVG 与预览 PNG。

### 重建管线

```
data.js（尺寸与证据标签）
   │
   ├─ 1. 碗体轮廓   BOWL_INNER 半宽 X/Z，四直段 + 四段 90° 角弧
   ├─ 2. 看台剖面   每座看台逐层（tier）按 台阶高/排距/排数 生成阶梯台阶体
   ├─ 3. 座席       在台阶面上按 座宽/排距 铺座席（可开关，默认开启）
   ├─ 4. 屋盖       半透明屋面板 + 径向主桁架 + 环向次梁 + 平面斜撑 + 檐口梁
   ├─ 5. 外立面     勒脚 + 玻璃幕墙（米级 UV 分格）+ 铝梃 + 腰线 + 压顶
   ├─ 6. 场地       草坪（条纹 + 标线 + 球门 + 角旗）、球门线/边线缓冲带
   ├─ 7. 内部元素   球员通道（西南角）、教练席、大屏、场边广告板、两座雕像
   ├─ 8. 泛光灯     屋盖一体化灯带 × 4 组（22 m / 2400 lux 口径）
   ├─ 9. 四角象限   四段 90° 角弧各自的看台体与屋盖
   ├─ 10. 外观结构  屋盖桅杆门架（含塔间格构带）、四角核心筒、外墙标识
   └─ 11. 周边配景  道路、停车场、运河、街区体块、天际线（示意性）
```

### 尺寸来源分级

`data.js` 中每个数值带以下标签之一：

| 标签 | 含义 | 举例 |
|---|---|---|
| `[官方]` | 俱乐部 / 政府 / 官方机构公开口径 | 容量 74,244（英超申报）、北看台 26,000 席 |
| `[文献]` | 权威体育场馆数据库、地方志、公开报道 | 北看台三层、177 级台阶、悬挑 58.5 m、通道在西南角 |
| `[推算]` | 由已知尺寸按常规建筑做法推导 | 大屏位置（对角布置）、LED 广告板尺寸 |
| `[推定]` | 缺少来源、按标准假定 | 草坪 105 × 68 m、排距、行距、环廊宽度 |

**页面与 `data.js` 双向一致**：档案抽屉里的每一行统计都能在 `data.js` 中找到出处，
README 与本文件中的数字也都来自同一份数据。

### 外观精细化：`EXTERIOR` 数据契约

2026-10 的一轮改进专门针对**从外面看得见的形状**（`js/data.js` 第 7b 节 `EXTERIOR`，
数据版本升到 2）。**看台与座席几何未作任何改动**，76,087 席与 258 排与旧版逐位一致。
所有外观尺寸同样是「可从 `data.js` 追溯的推算值」，标签沿用同一套分级：

| 外观构件 | 关键参数（`EXTERIOR.*`） | 依据 |
|---|---|---|
| 玻璃幕墙 | `facade.mullionSpacing 2.6` / `transomSpacing 3.2` | [推算] 照片立面分格比例换算 |
| 外凸铝梃 | `finSpacing 5.2` / `finWidth 0.30` / `finDepth 0.45` | [推算] |
| 勒脚 / 腰线 / 压顶 | `plinthHeight 5.4` / `beltY 15.0` / `copingHeight 1.10` | [推算] |
| 屋盖主桁架 | `trussSpacing 5.2` / `trussDepth 1.80` / `trussChord 0.34` | [照片] 16_2 鸟瞰桁架网格 |
| 环向次梁 / 斜撑 | `ringSpacing 5.2` / `diagonalEvery 2` | [推算] 控制三角面数 |
| 屋面板 | `panelOpacity 0.55`（半透明，仰视可见桁架） | [照片] 9_2 / 12_2 内场仰视 |
| 屋盖桅杆门架 | `count{北5/南3/东3/西3}` / `size 2.8` / `rise 17.0` / `insetFromBack 14.0` | [照片测算] 13_2 东立面可见 3 座 |
| 四角核心筒 | `size 14.0` / `heightRatio 0.92` / `trimEvery 4.5` | [照片] 16_2 四角灰白金属体 |
| 东立面横幅 | `bannerEast 50.0 × 9.5 m`，底标高 12.6 | [照片] 16_2「THE REDS / GO MARCHING ON!」 |
| LED 字标 | `wordmark`：东「MANCHESTER UNITED」30.0 × 2.4 m；西「STRETFORD END」26.0 × 2.4 m；夜间自发光 | [照片] 13_2 东 / 10_2 西 |
| 檐口饰带 | 西「STRETFORD END」30.0 × 2.0；北「SIR ALEX FERGUSON STAND」34.0 × 1.9 | [照片] 10_2 檐口白字 |
| 门店招牌 | 东立面「MEGA STORE」13.0 × 1.6，底标高 3.2 | [照片] 13_2 底部金字 |

要点：

- **米级 UV**：`gridToGeometry(grid, uvScale)` 现在能生成以米为单位的 UV，
  幕墙纹理的 `repeat` 直接用「每 2.6 m 一根梃、每 3.2 m 一道横梁」设定，**不猜贴图比例**；
- **构件级结构**：屋盖不是贴图，而是真的逐根搭出上下弦、腹杆、次梁与斜撑（`member(a,b,w,h)`），
  桅杆也是 4 根弦杆 + 每节水平环 + 斜腹杆的格构柱，因此**剖切、透明、阴影都对**；
- **零素材**：横幅、字标、饰带全部用 Canvas 现画（`makeBannerTexture` / `makeTextTexture`
  / `makeFasciaTexture`），文字面用 `alphaTest` 裁切，不引入半透明排序问题；
- **夜间**：LED 字标、门店招牌、幕墙内透光随 `setNight(true)` 一起点亮；
- **屋盖透明度滑杆**现在同时作用于屋面板、桁架与檐口梁，拉到 100% 时结构只剩骨架。

外观的**不确定度**：桅杆高度、横幅宽度、桁架间距等属于照片比例换算，绝对尺寸按 ±15% 计；
四角核心筒的位置由相邻两座看台后墙端点取中算出（真实建筑此处是斜向过渡），属于示意性重建。

### 图纸集：逐层平面图与剖面图（06—12）

`tools/gen-level-sheets.mjs` 由 `js/data.js` 直接推出图纸，**图上没有一处手写坐标**：
碗体轮廓取 `BOWL_INNER` 的圆角矩形，逐排踏面取各看台 `tiers` 的
`startDepth / rows / rowDepth / rowRise / baseHeight`，屋盖前缘取
`backDepth − roofCantilever`（下文称「口径 A」）。运行 `node tools/gen-level-sheets.mjs`
即可覆盖重建 06—12 号图，出图约 0.5 s。

| 图号 | 图名 | 层楼面 | 剖切标高 | 剖切落点（模型口径） |
|---|---|---|---|---|
| 06 | 场地层平面图 | ±0.00 | +1.20 | 草坪上方，不切割任何层段 |
| 07 | 首层看台平面图 | +2.20 | +3.60 | 四座看台 L1 @ 进深 8.5 m |
| 08 | 中层环廊平面图 | +18.00 | +19.40 | 北 / 东 / 西看台 L2 @ 37.5 m |
| 09 | 上层环廊平面图 | +33.20 | +34.60 | 北看台 L3 @ 65.0 m |
| 10 | 屋面层平面图 | 檐口 +49.00 | +49.60 | 檐口之上，只表达屋盖轮廓 |
| 11 | 逐层剖面谱 | — | 2—2 南北 1:500、3—3 东西 1:600 | 五条剖切标高线同时标注，附逐层剖切对照表 |
| 12 | 角部象限专项图 | +18.00（角部） | +19.40 | NE 角部平面 1:530 + 45° 对角剖面 1:650 |

**剖切口径**：各层平面的剖切标高 = 该层楼面 + 1.40 m（栏杆高口径）。因为逐排踏面上下
两个坡面的间距是 `1.40 ÷ 0.42 × 0.75 = 2.50 m`，所以四座看台的红色剖切线**永远**
落在被切层段内缘进深 +2.50 m 处 —— 这不是巧合，而是 `rowRise 0.42 / rowDepth 0.75`
这两个参数决定的；图中已把该口径写在 11 号图的剖切对照表下方。

**四角象限**：`data.js` 把四角 2005–06 象限写成独立数据块（`QUADRANTS.corners`，
每角 30 排、底 +18.00 m、顶 +30.60 m），而 `js/stadium.js` 只建立角部空组 ——
角部座席实际由相邻看台 L2 的 45° 弧段各半承担，两者在平面投影上完全重合。
12 号图把「数据口径 / 模型口径」并列画出，不做取舍。

**照片与模型的差异（已标注在图上，不并入几何）**：

1. **屋盖前缘有两种读法**。模型用「口径 A」（前缘 = 看台声明外缘 − 悬挑），
   北看台因此落在进深 26.5 m；而 `data.js` 的官方口径是「自碗体内缘向后悬挑 58.5 m」。
   10 号图以虚线示出官方读法下的前缘作为对照，不参与几何。
2. **四角白色格构桁架（桅杆）** 在用户提供的现场照片中很显眼，模型未建立。
3. **座席白字拼写**（`MANCHESTER UNITED` / `STRETFORD END`）见于照片，
   属装饰图案，不参与几何。

## 六、数据契约 `js/data.js`

纯数据模块，无副作用、不依赖 Three.js，可单独被工具链引用
（`tools/gen-drawings.mjs` 就只 import 它）。

| 导出 | 内容 |
|---|---|
| `DATA_VERSION` | 契约版本号 |
| `META` | 球场元信息：坐标、启用年、容量口径（英超 / 欧战 / 仅座席）、分看台座席、历史最高上座 |
| `PITCH` | 草坪 `length` / `width` / `orientation` |
| `RUN_OFF` | 球门线与边线缓冲宽度 |
| `BOWL_INNER` | 碗体内缘半宽 `halfX` / `halfZ`、直段长度、角弧半径 |
| `SEATING` | 座宽、排距、排高、通道间隔、各看台座席口径 |
| `STANDS` | 四座看台的完整档案：层数、各层排数与坡度、屋盖悬挑、外立面、历史沿革 |
| `STAND_ORDER` | 看台渲染顺序 |
| `QUADRANTS` | 四角象限的角弧划分（各 90°，按 45° 分属相邻两座看台） |
| `FEATURES` | 通道、教练席、大屏、泛光灯、广告板、雕像 |
| `CONTEXT` | 周边道路、停车场、运河、街区 |
| `COLORS` | 全部材质颜色（供 UI 色块与几何共用） |

| `SOURCES` | 来源清单，每项带 `status: ok \| blocked` 与 `tier` |
| `DISCLAIMER` | 精度声明（短句 + 长条款），页面与 README 同步展示 |

## 七、几何生成器 `js/stadium.js`

```js
import { buildStadium } from './js/stadium.js';

const model = buildStadium({
  seats: true,        // 是否铺座席
  context: true,      // 是否生成周边配景
  deckStep: 2.6,      // 台阶采样步长
  seatStep: 1,        // 座席采样步长
});

model.root              // THREE.Group，直接 scene.add()
model.parts             // { standNorth, standSouth, standEast, standWest, roof, exterior, pitch, context, … }
model.bounds            // 相机取景用包围盒（不含远景）
model.stats             // { seats, triangles, meshes, seatRows, buildMs, bowl, … }
model.setSeatMode(mode) // 'natural' | 'block' | 'capacity' | 'away' | 'hidden'
model.setSection(v)     // 0–1 看台分离
model.setRoofVisible(b) // 屋盖显隐
model.setRoofOpacity(v) // 0–1 屋盖透明度（屋面板 + 桁架 + 檐口梁）
model.setContextVisible(b)
model.setNight(b)       // 泛光灯 / 大屏 / LED 字标 / 幕墙内透光
model.setTimeOfDay(h)   // 0–24，返回 { altitude, azimuth }
```

内部结构（便于二次开发）：

```js
buildDeck(stand, M, deckStep)   // 4.1 台阶面 · 4.2 前栏板 · 4.3 外墙（勒脚/幕墙/铝梃/腰线/压顶）
                                // 4.4 屋盖（桁架 + 半透明板 + 檐口梁）· 4.5 两端封墙 · 4.6 座席排布
buildExterior(M)                // 屋盖桅杆门架 + 塔间格构带 + 四角核心筒 + 外墙标识
gridToGeometry(grid, uvScale)   // 扫掠网格 → BufferGeometry；uvScale>0 时生成米级 UV
member(a, b, w, h)              // 两点之间的杆件（桁架/桅杆的基本构件）
canvasTexture / makeFacadeTexture / makeBannerTexture / makeTextTexture / makeFasciaTexture
```

**性能取舍**：座席是 191 万三角面里的绝大多数（1,826,088）。若在低端设备上需要提速，
把 `seats` 设为 `false` 或把 `seatStep` 设为 `2` 即可（三角面约降为 1/4）。
当前实现在普通独显上构建约 270–370 ms，全程同步、无网络请求。

## 八、已知偏差与诚实清单

这一节是本项目的核心态度：**把所有"不知道"的地方明确列出来**。

1. **草坪尺寸 105 × 68 m 是按标准假定**，未取得老特拉福德实测来源。
2. **排数、行距、排高、层间环廊宽度均为重建值**。已知的官方数据只有：
   北看台三层、悬挑 58.5 m、台阶 177 级；南看台单层；容量 74,244（英超申报）。
3. **外立面材质、分格、屋顶形态为重建**；未取得任何官方建筑图纸。
4. **大屏位置为推算**（对角布置），未取得官方来源。
5. **周边道路、停车场、地标方位取自公开来源与实测核查**，但坐标为示意性反推，非测绘成果。
6. **公开渠道确实取不到施工图级图纸**。这是本次调研的否定性结论之一：
   老特拉福德的建筑图纸未进入任何公开档案库（详见 `研究/03-规划图纸与尺寸.md`）。
   获得更高精度的唯一现实路径是**自行地面摄影测量**，计划见
   `老特拉福德拍摄计划-地面摄影测量.md`。
7. **生成座席数（76,087）与英超申报容量（74,244）不一致**，这是有意的：
   前者是几何排布的结果，后者是官方申报口径。页面两处分别标注，不做调和。
8. **坐标与朝向**：模型采用"北 = −Z"的平面约定，与页面显示的 53.4631°N / 2.2913°W
   仅表示场地位置，不构成坐标换算成果。
9. **06—12 号图纸是「重建图」，不是测绘成果**：它们的每个尺寸都来自 `js/data.js`，
   而 `data.js` 里的排距、行距、环廊宽度仍是 `[推定]`。图纸的确定性不会高于数据 ——
   改一个数、重跑一次 `node tools/gen-level-sheets.mjs`，全套图随之改变。
   图上凡是用到 `[推定]` / `[推算]` 值的地方，图例与右侧面板都标了来源等级。

## 九、版权与合规

### 本项目的原创内容

`index.html`、`styles.css`、`js/*.js`、**12 张 SVG 工程图**、全部文本 —— 原创。

### 第三方依赖

**Three.js r169**（MIT 许可），已**完整本地化到 `vendor/`**，运行期零外链、零 CDN、
零遥测。`vendor/` 内的文件保持上游原样，未作修改。

### 影像素材

**本项目未嵌入任何照片素材。** 原因不是偷懒，而是权利问题：

- Wikimedia Commons、Historic England 影像库在本机网络环境下不可达（已实测记录 status）；
- Trafford 地方研究馆藏的条款明确要求：任何**公开展览、出版物、产品**用途
  必须事先取得书面 `Permission to Reproduce`，且授权"仅覆盖当次申请用途"；
- 因此本项目采用**"零照片"策略**：几何全部程序化生成，材质为纯色/程序化纹理。

> 一处需要说清楚的区分：**外观精细化（`EXTERIOR`）的参数是照着现场照片量的**，
> 这些照片由项目方自行拍摄、**未随本项目分发**，`assets/` 里没有任何照片文件；
> 模型里呈现的花纹与文字全部由 Canvas 现画。照片的作用是"量尺寸的参照"，
> 不是"贴图的来源"——这两件事在版权上完全不同（详见 `研究/04-照片素材与版权.md`）。

详见 `研究/04-照片素材与版权.md`（含 CC 各版本对展览用途的含义分析、中国著作权法下的
展览权分析、以及一份 12 类建模照片的拍摄清单）。

### 商标

**不复制任何注册商标图形。** 俱乐部徽章、队徽、赞助商标识均未使用：
横幅上的徽章位置是**抽象几何占位**（金色圆环 + 斜线，见 `makeBannerTexture`）。

立面文字标识（`MANCHESTER UNITED`、`STRETFORD END`、`SIR ALEX FERGUSON STAND`、
`THE REDS`、`MEGA STORE`）是**按照片复原的文字**，属于文字商标的使用范畴。
如果需要一场**零商标风险**的展出，把 `js/data.js` 里 `EXTERIOR.signage.enabled`
改为 `false`：外墙上的横幅、字标、饰带、招牌会全部消失，建筑几何不受影响。

详见 `研究/04-照片素材与版权.md`：该文件建议公开展览中"不出现队徽与 Manchester United 字样"，
展签统一写"**老特拉福德球场（非官方模型）**"。上面的开关就是为这条建议准备的。

## 十二、如何进一步提高精度

按性价比排序：

1. **自行地面摄影测量**（最高性价比）—— 20–40 个机位、航向重叠 ≥ 70%、
   旁向重叠 ≥ 60%、固定焦距与白平衡、RAW 优先，可得到 5–20 mm 级细部。
   完整计划见 `老特拉福德拍摄计划-地面摄影测量.md`。
2. **英国环境署 LiDAR 开放数据**（OGL 许可，可商用）—— 1 m / 2 m DSM 可修正
   屋面轮廓与周边地形，但没有建筑类别，无法替代建筑图纸。
3. **NCAP 国家航拍收藏**（按需扫描服务）—— 历史航拍可校准 1910/1996/2001/2006
   各期形态演变。
4. **Trafford 地方研究馆藏**（付费研究服务）—— 唯一可能藏有早期立面图纸的机构，
   需走线下检索与书面授权。
